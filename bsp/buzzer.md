# buzzer.c 有源蜂鸣器驱动说明

## 接线与默认状态

PB15 为高电平触发信号，低电平关闭。三脚有源蜂鸣器模块的信号输入必须兼容 3.3 V，VCC 按模块额定电压连接，GND 与 STM32 共地。裸两脚蜂鸣器需要匹配的晶体管驱动，不能由 PB15 直接供电。

`Buzzer_Init()` 开启 GPIOB 时钟，先把 PB15 输出锁存器置低，再配置为 2 MHz 推挽输出，防止初始化时误鸣。复位到软件初始化之前仍应依赖模块自身或外部下拉保持关闭。

## 非阻塞提示序列

本驱动不引用 FreeRTOS、不延时、不忙等、不分配内存。正常运行时只允许蜂鸣器任务访问播放状态。

| 接口 | 行为 |
| --- | --- |
| `Buzzer_Start(pulses, now)` | 开始 1～4 声提示，新命令立即打断旧序列；0 声表示停止，超过 4 声按 4 声处理 |
| `Buzzer_Update(now)` | 根据毫秒时间推进输出；建议播放期间每 10 ms 调用一次 |
| `Buzzer_IsBusy()` | 返回是否还有未结束的序列 |
| `Buzzer_Stop()` | 立即关闭，初始化前也能调用；故障路径使用后应停止系统，不恢复旧序列 |

每声持续 200 ms，声间间隔 150 ms。最后一声结束即关闭，不计入尾部间隔。1～4 声的总时长分别为 200、550、900、1250 ms。

状态按 `now - start_tick` 的无符号差计算，能跨越 32 位毫秒计数回绕。若任务被延迟，驱动直接输出当前应有的相位，不补发过期脉冲、不在延迟基础上继续累积误差。运行期间应持续调用更新，不能跨越完整的 32 位计数周期而完全停止更新。

普通提示、结束提示及错误提示的命令选择由应用层决定；驱动仅执行脉冲序列，不修改页面、倒计时、门或加热状态。

## 故障关闭

`Buzzer_Stop()` 不使用 RTOS API，可从系统终止型故障路径调用。如果硬件还未初始化，它会先建立 PB15 的安全低电平输出；仅操作 GPIOB 时钟和 PB15，不修改其他引脚。该接口不等于可并发播放：若在中断中关闭，调用方必须保证之后不会返回到正常播放流程。

## 验证要点

- 上电 PB15 默认低，空闲时保持低，不产生声音。
- 逐项核对 1～4 声、200 ms 声长、150 ms 间隔和最后一声的关闭边界。
- 连续调用更新不能重新触发当前提示；新命令应打断旧提示。
- 大幅延后更新时不补发短脉冲；跨 Tick 回绕仍按正确时长结束。
- 初始化前停止、播放中停止均保持 PB15 低，且不依赖调度器。
