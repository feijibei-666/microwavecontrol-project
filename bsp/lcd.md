# lcd.c ST7735 硬件 SPI 显示驱动

## 引脚与外设

| 屏幕信号 | STM32 引脚 |
| --- | --- |
| CLK / SCK | PA5，SPI1 SCK |
| SDA / MOSI | PA7，SPI1 MOSI |
| RS / DC | PB7，GPIO 输出 |
| RST | PB8，GPIO 输出 |
| CS | PB9，GPIO 输出 |

接线与原工程一致。SPI1 使用单线只发送、主机模式、8 位、MSB 先行、模式 3（空闲高、第二边沿采样），72 MHz 总线默认 8 分频为 9 MHz。软件 NSS 内部置高，CS 由 PB9 独立控制，无需 MISO。

使用 DMA1_Channel3 发送 SPI1 TX 数据，不启用 DMA 中断；中断向量仍由 FreeRTOS 管理其系统异常。独占该 SPI/DMA 通道，其他模块不可同时重新配置。

## 数据与内存

`LCD_Blit(x, y, width, height, pixels)` 接收原生 16 位 RGB565 数组。驱动使用一个静态 256 字节行缓冲，将每个像素转为高字节先发，再由 8 位 DMA 发送；不分配全屏 framebuffer，也不通过大数组占用任务栈。

- 非法坐标、0 尺寸或空指针直接返回。
- 超出屏幕右边、底边的区域裁剪；源数据每行跨度始终是调用者传入的原始 `width`。
- DMA 每行最多 256 字节，发送完成后继续等待 SPI TXE 和 BSY，确保最后一位已移出再切换 CS/DC。
- 所有传输同步返回，传输期间没有关闭中断；高优先级按键与控制任务可以抢占 UI 任务。
- 只能由显示任务调用 LCD API，防止行缓冲和 SPI 命令交叉。不需要给其他任务开放 LCD 锁。

`LCD_FontColumn(ch, column, half)` 提供原 8×16 ASCII 字库某一列，`column=0..7`、`half=0..1`，用于小带缓冲中的渲染；原字库数据保持不变。

原有 `LCD_Fill`、`LCD_Clear`、字符和字符串接口保留；字符绘图临时使用 256 字节栈缓冲。新的 UI 主要使用分片 `LCD_Blit`，不逐像素通过 SPI 写入。

## 初始化与延时

保留原 ST7735 初始化命令序列及方向、偏移、反色配置。初始化在调度器启动后的显示任务调用，因此所需毫秒等待由 `delay_ms()` 使用任务延时完成，不阻塞输入和控制任务。

颜色、坐标偏移如与实物屏幕不匹配，需要在实际硬件上核对 `CMD_MADCTL`、`CMD_INVON`、`LCD_X_OFFSET`、`LCD_Y_OFFSET`。

## 超时与故障

SPI 等待和每行 DMA 等待都有 50 ms 时间上限，同时具有限定次数的循环兜底，避免系统时间不走时无限等待。

| `lcd_fault_code` | 含义 |
| --- | --- |
| 0 | 正常 |
| 1 | SPI TXE / BSY 等待超时 |
| 2 | DMA 完成超时 |
| 3 | DMA 传输错误 |

发生故障时关闭 SPI TX DMA、DMA 通道及 SPI，清 DMA 标志并释放 CS。后续绘图直接返回，控制逻辑不会被无限卡住；上层应检查故障码并进入故障处理。重新调用 `LCD_Init()` 会清故障码并重新初始化。

长杜邦线或供电、地线质量较差时，可降低 `LCD_SPI_PRESCALER` 对应速度后实机测试。屏幕电源与背光接法仍以模块规格为准。
